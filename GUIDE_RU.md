# Как устроен проект

Это небольшая самостоятельная проверка идеи из [статьи NeurIPS 2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/2ee1c87245956e3eaa71aaba5f5753eb-Paper-Conference.pdf): можно ли один раз подобрать хорошие настройки CatBoost на нескольких задачах и затем использовать их на новых задачах.

**Датасет** — таблица с признаками (входными столбцами) и целевым столбцом, который модель предсказывает. Здесь шесть открытых таблиц из UCI и четыре из OpenML. Все десять используются как задачи регрессии: модель выдаёт число. У Wine Quality и Abalone целевые значения целые, но мы всё равно предсказываем их как числа и измеряем ошибку регрессии.

**Гиперпараметры** — настройки обучения, например глубина дерева и скорость обучения. **Дефолт** — набор настроек, с которым модель запускается без отдельного поиска для каждой таблицы. В проекте сравниваются дефолт текущей установленной версии CatBoost, настройки из статьи, свой общий набор и отдельный подбор под каждую новую таблицу.

**Meta-train** — шесть таблиц, на которых мы выбираем свой общий набор. **Meta-test** — четыре другие таблицы, на которых проверяем, перенесётся ли он. Настройки нельзя выбирать по результату meta-test: тогда проверка потеряет смысл.

Каждую таблицу мы делим на 60% для обучения, 20% для выбора настроек и числа деревьев, 20% для итоговой проверки. Это разные строки. После выбора числа деревьев модель заново обучается на первых 80% и выдаёт прогноз для последних 20%.

**RMSE** — средняя квадратичная ошибка в исходных единицах целевого столбца. **nRMSE** делит RMSE на стандартное отклонение целевого столбца в обучающей части. Так можно осторожно сравнивать таблицы с разными единицами измерения. Чем меньше ошибка, тем лучше. Результат на десяти таблицах не доказывает, что одна настройка всегда сильнее другой.

В первом запуске на десяти таблицах (одно разбиение, максимум 300 деревьев) агрегированная nRMSE на четырёх новых задачах составила 0.4733 для библиотечного дефолта, 0.4528 для настроек статьи, 0.4532 для нашего общего набора и 0.4521 для отдельного поиска с пятью попытками. Это описание маленького эксперимента, а не доказательство превосходства метода. Таблица по каждой задаче есть в `README.md`.

## Что лежит в файлах

| Файл | Назначение |
| --- | --- |
| `datasets.py` | Список таблиц, скачивание с UCI и OpenML, сохранение локального кеша, проверка целевого столбца и категорий. |
| `configs.py` | Настройки из статьи и небольшой набор для нашего поиска. |
| `experiment.py` | Разделение строк, обучение, вычисление ошибок. |
| `run_experiment.py` | Запуск сравнения и сохранение результатов. |
| `plot_results.py` | График ошибок на двух новых таблицах. |
| `tests/test_protocol.py` | Проверка долей и непересечения частей данных. |
| `README.md` | Описание проекта для портфолио и команды запуска. |
| `.gitignore` | Правила Git, которые не дают добавить данные, кеш и промежуточные результаты. |

## Самый простой запуск

Открой PowerShell в папке проекта и выполни команды из раздела **Run locally** в `README.md`. Сначала используй `--smoke`: это короткая проверка, что зависимости установились и код работает. Потом запускай пилот на шести таблицах. Его результаты появятся в `results/raw/`; эта папка останется на твоём компьютере.

Если запускать через Google Colab, последовательно выполни ячейки `!git clone https://github.com/y4rik2009-bit/catboost-better-defaults-study.git`, `%cd catboost-better-defaults-study`, `!pip install -r requirements.txt` и `!python run_experiment.py --smoke`. После короткой проверки можно взять команду пилота из `README.md`. GPU не нужен. В GitHub никакие личные данные и прежний датасет РТО не загружаются.

## Как потом обновлять GitHub

На странице репозитория открой нужный файл, нажми значок карандаша (**Edit this file**), измени текст и нажми **Commit changes**. Коммит — сохранённая версия изменений с коротким описанием. Если добавляешь новые файлы через **Add file → Upload files**, выбирай только исходный код и документацию. Не выбирай `.cache`, `results/raw`, исходные таблицы или файлы с личными данными. Правила `.gitignore` защищают при обычной работе через Git, но не заменяют проверку файлов при ручной загрузке через браузер.

## Как рассказывать о проекте на собеседовании

«Я взял идею из статьи NeurIPS 2024 о переносимых настройках моделей для табличных данных. Сравнил стандартный CatBoost, настройки авторов, свой общий набор и отдельный поиск настроек на десяти открытых задачах регрессии. Разделил задачи на meta-train и meta-test, а строки каждой задачи на обучение, валидацию и тест, чтобы не подбирать настройки по тесту. Результаты и ограничения эксперимента описал в README».
